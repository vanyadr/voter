# Voter

Небольшое приложение для кейс-чемпионата: **4 участника, 2 члена жюри, 20 анонимных бланков**. Next.js App Router, TypeScript, Tailwind CSS, Supabase Postgres. Подходит для деплоя на Vercel.

## Возможности

- Вход по личному случайному коду без регистрации.
- Участники оценивают троих других участников; жюри — всех четверых.
- Шесть целочисленных оценок от 1 до 5 в каждом бланке.
- До отправки оценки можно менять; после отправки бланк доступен только автору для просмотра.
- Оба члена жюри могут подготовить мероприятие, изменить имена, выпустить коды и открыть голосование.
- Правила, имена и коды фиксируются при открытии.
- После двадцатого бланка голосование автоматически завершается, а обоим членам жюри открывается рейтинг.
- В кабинете жюри виден только общий прогресс, без списка проголосовавших и чужих бланков.
- После завершения можно создать следующее мероприятие. Старые результаты доступны по старым кодам жюри.
- Интерфейс адаптирован для телефона. Данные обновляются каждые 15 секунд, пока голосование не завершено.

## Подсчёт

Порядок критериев совпадает в `src/lib/model.ts` и SQL-миграции:

| Критерий             | Вес |
| -------------------- | --: |
| Юзабилити приложения |   3 |
| Необычные фичи       |   3 |
| Дизайн               |   2 |
| Качество выступления |   2 |
| Интересность идеи    |   1 |
| Качество презентации |   1 |

Балл бланка: сумма `оценка × вес`, от 12 до 60.

**Итог = 70% × средний балл двух жюри + 30% × средний балл трёх других участников.**

При равенстве итогов выше тот, у кого больше средний балл жюри. При полном равенстве — общее место (например, 1, 1, 3, 4). SQL сравнивает целочисленные числители `(21 × сумма жюри + 6 × сумма участников)` с общим знаменателем 60. Округление до сотых применяется только для отображения.

Правила версии 1 фиксированы. При изменении критериев для будущих мероприятий нужно добавить новую версию правил и миграцию, сохранив расчёт старой версии.

## Быстрый запуск

Нужны Node.js 22+ и проект Supabase.

1. Установите зависимости:

   ```bash
   npm ci
   ```

2. Создайте бесплатный проект в [Supabase](https://supabase.com/dashboard). В **SQL Editor** выполните **один раз целиком** файл [`supabase/migrations/20261101000000_voter.sql`](supabase/migrations/20261101000000_voter.sql). Используйте новый проект или предварительно проверьте, что таблиц с такими именами нет. Миграция выполняется в транзакции, не удаляет существующие данные и при конфликте откатится.

3. Скопируйте `.env.example` в `.env.local`. Укажите:

   | Переменная                  | Значение                                                                                        |
   | --------------------------- | ----------------------------------------------------------------------------------------------- |
   | `SUPABASE_URL`              | Project URL из настроек Data API                                                                |
   | `SUPABASE_SERVICE_ROLE_KEY` | Серверный secret key (`sb_secret_…`) или legacy `service_role` key, **не** publishable/anon key |
   | `APP_SECRET`                | Случайный секрет длиной не менее 32 символов                                                    |
   | `BOOTSTRAP_CODE`            | Отдельный случайный код первичной настройки, не менее 12 символов                               |

   Сгенерировать два последних значения:

   ```bash
   npm run secrets
   ```

   Сохраните их в менеджере паролей и перенесите в `.env.local`. Вывод команды содержит секреты — не публикуйте его. Переменные сервера не должны иметь префикс `NEXT_PUBLIC_`.

4. Запустите приложение:

   ```bash
   npm run dev
   ```

5. Откройте `http://localhost:3000`, войдите с `BOOTSTRAP_CODE`, укажите название, имена четырёх участников и двух членов жюри.
6. **Сохраните все шесть выданных кодов, включая свой код первого члена жюри.** Они показаны один раз. После создания вы автоматически входите как первый член жюри. Передайте каждому только его личный код.
7. Проверьте имена, сохраните изменения при необходимости и откройте голосование.

После первого мероприятия `BOOTSTRAP_CODE` больше не даёт доступ. Дальнейшее управление — по кодам жюри. До открытия голосования можно перевыпустить весь комплект кодов; уже открытые сессии останутся действительными до выхода или истечения 24 часов.

## Деплой на Vercel

1. В [Vercel](https://vercel.com/new) импортируйте репозиторий `vanyadr/voter`.
2. Framework Preset: **Next.js**, Node.js: **22.x или 24.x**. Build Command: `npm run build`. Production Branch: **main**.
3. Добавьте четыре переменные из `.env.example` в окружение **Production**. Для Preview используйте отдельный тестовый Supabase-проект и отдельные секреты, чтобы проверки не затрагивали настоящее голосование.
4. Убедитесь, что SQL-миграция уже выполнена в выбранном Supabase-проекте.
5. Нажмите **Deploy**. Откройте выданный HTTPS-адрес и пройдите первичную настройку.

Настоящие коды создавайте уже по адресу production. Изменение `APP_SECRET` аннулирует сессии и делает сохранённые хеши кодов несовместимыми; не меняйте его во время мероприятия. Он нужен и при повторном использовании базы.

Для небольшого мероприятия ресурсов бесплатного Supabase обычно достаточно. Бесплатные проекты могут приостанавливаться при неактивности: проверьте доступность базы заранее. Условия Vercel Hobby требуют соответствующего некоммерческого использования; проверьте применимость к своему мероприятию. Бесплатные тарифы и их лимиты могут меняться.

## Проверки

```bash
npm run typecheck
npm test
npm run build
```

Тесты исполняют настоящую SQL-миграцию в локальном PostgreSQL-движке PGlite; внешний Supabase и ключи не нужны. Покрыты валидация оценок, запрет самооценки, роли, параллельная повторная отправка, неизменность бланка, двадцатая отправка, точный подсчёт, ничьи, перевыпуск кодов, повторное мероприятие, защита сессий и ограничение входа.

Сборка использует поддерживаемый Webpack-режим Next.js, чтобы не зависеть от локальных сокетов рабочих процессов Turbopack в ограниченных средах CI.

## Данные и доступ

- Только сервер Next.js обращается к Supabase через HTTPS Data API; браузеру ключ базы не передаётся.
- На всех таблицах включён RLS, у `anon` и `authenticated` нет прав ни на данные, ни на RPC. `service_role` может читать таблицы, но изменять их — только через разрешённые транзакционные RPC.
- Роль и автор бланка определяются из подписанной HttpOnly-сессии, а не из полей браузера. Cookie действует 24 часа, имеет SameSite=Lax и Secure в production. Мутации идут через Server Actions с проверкой Origin, встроенной в Next.js.
- Коды имеют 64 бита случайности и хранятся как HMAC-SHA256 с `APP_SECRET`. Подписи сессий проверяются с constant-time сравнением.
- Ограничение входа хранится в БД: 15 попыток на 15-минутное окно для IP. На Vercel используется заголовок `x-vercel-forwarded-for`, который платформа перезаписывает. На других хостингах — общий лимит; перед таким деплоем настройте извлечение IP из доверенного заголовка своего прокси.
- Отправка бланка, проверка статуса и завершение голосования сериализуются блокировкой мероприятия в одной транзакции. Повторы дополнительно блокирует уникальный индекс.
- Анонимность действует **в интерфейсе приложения**. Владелец Supabase и серверного ключа технически имеет доступ к исходным данным, включая связь автора с бланком.
- Сброс оценок и аварийное закрытие неполного голосования не предусмотрены: итоги появляются строго после всех 20 бланков. Если человек не сможет проголосовать, мероприятие останется открытым.
- Текущая версия рассчитана на 4 участников и 2 жюри в каждом мероприятии; произвольное число людей потребует изменения правил и модели.

## Структура

```text
src/app/                 страницы и серверные действия
src/components/          интерфейс входа, голосования и кабинета жюри
src/lib/                 модель, криптография, доступ к данным
supabase/migrations/     таблицы, ограничения, транзакционные RPC
tests/                   проверки правил и доступа
scripts/                 генерация секретов
```
